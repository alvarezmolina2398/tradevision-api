Documentacion de integracion
API de analisis visual de establecimientos comerciales
Version 1.0 | 28 de agosto de 2026

1. Informacion general

La API analiza una o varias imagenes de un negocio. Segun el motivo del negocio y las imagenes, aplica uno de dos flujos:

  • Tradicional (businessFlow: "traditional"): comercios y microemprendimientos. Estima metricas comerciales, inventario, herramientas de trabajo, gastos, utilidad y puntuaciones visuales.
  • Cultivos (businessFlow: "crop"): produccion agricola. Estima unidad de venta, precios, ciclo de cosecha, cuidados, gastos, produccion esperada, mercado local, riesgo, salud de las plantas y limpieza del terreno.
URL basehttps://innova.genesisempresarial.com/genesis-estimator
FormatoJSON para respuestas; multipart/form-data para el analisis.
AutenticacionHeader x-api-key, requerido unicamente en /analyze.
Documentacion interactivahttps://innova.genesisempresarial.com/genesis-estimator/docs
Seguridad: la clave API no se incluye en este documento. Guardala en una variable de entorno o en el gestor de secretos de tu plataforma. Como la clave fue compartida en una conversacion, se recomienda revocarla y generar una nueva.

3. Analisis de establecimiento

POST/analyze

Analiza imagenes del establecimiento o cultivo. Requiere una API key valida y una peticion multipart/form-data. El flujo (tradicional o cultivos) se determina automaticamente a partir de productType y de las imagenes; un local que solo revende productos agricolas se trata como negocio tradicional.

Headers

HeaderValorObligatorio
x-api-keyTu clave privada de consumoSi
Content-TypeSe genera automaticamente como multipart/form-dataSi

Campos del formulario

CampoTipoObligatorioDescripcion
productTypeTextoSiTipo de producto, negocio o cultivo esperado (motivo del negocio).
specialObservationsTextoNoContexto adicional, por ejemplo condiciones del terreno, acceso o ubicacion, para ajustar las estimaciones. En cultivos se recomienda indicar la extension del terreno o el numero de plantas.
imagesArchivo, repetibleSiImagenes JPEG, PNG, WEBP o GIF.

Limites actuales: hasta 10 imagenes por solicitud y 10 MB por imagen.

Ejemplo con cURL

curl -X POST \
  "https://innova.genesisempresarial.com/genesis-estimator/analyze" \
  -H "x-api-key: TU_API_KEY" \
  -F "productType=abarrotes" \
  -F "specialObservations=Ubicado en una aldea; acceso de terraceria durante la lluvia" \
  -F "images=@./local.jpg" \
  -F "images=@./interior.png"

4. Respuesta exitosa

El campo businessFlow indica el flujo aplicado y determina la forma de details.

4.1 Flujo tradicional

{
  "status": true,
  "message": "análisis completado exitosamente",
  "businessFlow": "traditional",
  "details": {
    "matchesExpectedProductType": true,
    "estimatedMinimumRevenue": 5000,
    "estimatedExpectedRevenue": 8000,
    "estimatedMaximumRevenue": 12000,
    "estimatedAverageTicket": 35,
    "estimatedInventoryValue": 18000,
    "estimatedInventoryCoverageDays": 67.5,
    "estimatedMonthlyInventoryConsumptionPercentage": 44.4,
    "inventoryItems": [
      { "name": "Bebidas", "quantity": 24, "unitPrice": 8, "subtotal": 192 }
    ],
    "estimatedWorkToolsValue": 4500,
    "workTools": [
      { "description": "Refrigerador", "quantity": 1, "unitPrice": 4500, "approximatePrice": 4500 }
    ],
    "estimatedMonthlyExpenses": 5200,
    "estimatedMonthlyProfit": 2800,
    "productType": "Tienda de abarrotes",
    "cleanlinessScore": 82,
    "stockingScore": 76,
    "organizationScore": 80,
    "visibilityScore": 74,
    "overallStoreScore": 78
  }
}

Los importes son estimaciones en quetzales guatemaltecos. Para estimar la rotación, la API considera el giro, el ticket promedio, las ventas mensuales esperadas, los productos visibles y el tamaño típico de un micronegocio o negocio pequeño en una aldea o municipio, no de un comercio urbano grande. estimatedInventoryCoverageDays estima cuántos días duraría el inventario visible; el modelo lo estima considerando el ritmo de venta mensual atribuible a esos productos. estimatedMonthlyInventoryConsumptionPercentage se calcula a partir de los días estimados con un mes de 30 días: (30 / días de cobertura) × 100. Así los campos son coherentes entre sí; el porcentaje puede superar 100 si el inventario duraría menos de un mes. Si no hay inventario vendible visible, ambos son 0. Son aproximaciones, no datos de ventas observadas. En el ejemplo, Q18,000 de inventario frente a Q8,000 de ventas mensuales atribuibles representan 67.5 días de cobertura y aproximadamente 44.4% de consumo mensual. Los campos de puntuación son enteros de 0 a 100.

4.2 Flujo de cultivos

Valores ilustrativos; no son cotizaciones reales. El precio mostrado representa venta minorista rural al consumidor final.

{
  "status": true,
  "message": "análisis completado exitosamente",
  "businessFlow": "crop",
  "details": {
    "mainSalesUnit": { "name": "quintal", "description": "100 libras" },
    "matchesExpectedProductType": true,
    "cropType": "Maíz",
    "productPresentation": { "name": "Grano seco", "description": "Presentación común estimada para venta minorista rural." },
    "recentProductionPrices": { "minimum": 150, "maximum": 260, "average": 200 },
    "harvestCycle": { "minimumDays": 110, "maximumDays": 150, "description": "1 a 2 ciclos por año" },
    "careDetails": [
      { "activity": "Limpia", "description": "Deshierbe manual", "frequency": "2 por ciclo", "estimatedCost": 400 }
    ],
    "minimumExpectedExpenses": 2500,
    "expectedProduction": { "minimum": 20, "maximum": 35 },
    "localMarketHealth": { "score": 70, "status": "favorable", "description": "Demanda estable" },
    "riskPercentage": 35,
    "riskFactors": ["Sequía"],
    "plantHealthPercentage": 80,
    "landCleanlinessPercentage": 65
  }
}
CampoDescripcion
mainSalesUnitUnidad de venta principal (quintal, arroba, ciento, caja, etc.). Todas las cantidades y precios por unidad se expresan en ella.
productPresentationFormato comercial del cultivo. Si se especifica en productType o specialObservations, se respeta; si no, se estima la presentación más común para venta minorista rural. Precios y producción corresponden a esta presentación.
recentProductionPricesPrecio aproximado de venta al por menor al consumidor final en zonas rurales de Guatemala: minimo, maximo y promedio en quetzales por una unidad de mainSalesUnit (Q/quintal, por ejemplo). Se pueden usar precios del año anterior como referencia comparable, no como cotizacion actual verificada. La API no consulta automaticamente fuentes historicas externas.
harvestCycleTiempo estimado entre ciclos de cosecha, en dias.
careDetailsCuidados necesarios por cosecha, con frecuencia y costo estimado (Q).
minimumExpectedExpensesGastos minimos esperados por ciclo de cosecha (Q).
expectedProductionCantidad minima y maxima esperada por ciclo, en la unidad principal.
localMarketHealthSalud del producto en el mercado local: puntuacion 0-100, estado (muy favorable, favorable, estable, desfavorable, muy desfavorable) y justificacion.
riskPercentage / riskFactorsPorcentaje de riesgo (0-100) y principales factores.
plantHealthPercentagePorcentaje de salud de las plantas mostradas (0-100).
landCleanlinessPercentagePorcentaje de limpieza del terreno (0-100).

5. Errores

CodigoSignificadoCausa habitual

401 UnauthorizedAPI key invalida o ausenteHeader x-api-key incorrecto o no enviado.
413 Payload Too LargePayload excedidoMas de 10 archivos o una imagen mayor a 10 MB.
415 Unsupported Media TypeTipo no permitidoLa imagen no es JPEG, PNG, WEBP o GIF.
422 Unprocessable EntityTipo no relacionadoLas imagenes no corresponden al productType indicado.
502 Bad GatewayError del analisisNo se pudo completar la comunicacion con el servicio de IA.

6. Configuracion del servidor

En produccion define las variables de entorno sin subir el archivo .env al repositorio:

PORT=3000
HOST=0.0.0.0
API_KEY=TU_API_KEY
OPENAI_API_KEY=TU_OPENAI_API_KEY
OPENAI_MODEL=gpt-4o

El proceso se inicia con:

pnpm start

Si se ejecuta con systemd, el servicio debe cargar el archivo de entorno y arrancar src/server.js.

7. Recomendaciones de consumo

  • Usa siempre HTTPS y no expongas la API key en aplicaciones frontend publicas.
  • Envia imagenes enfocadas, legibles y relevantes para mejorar la estimacion.
  • No registres el header x-api-key en logs.
  • Rota la API key si fue compartida, comprometida o incluida accidentalmente en un repositorio.
